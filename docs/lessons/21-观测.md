# 第 21 课 · 观测

> 能力：onProviderStreamEvent、TTFT、durationMs、费用、telemetry　｜　场景：读懂一次请求的耗时构成　｜　里程碑：M6

## 讲解

读懂一次请求的耗时：排队等配额（灰色）→ TTFT（白色竖线，onProviderStreamEvent 收到首个 provider 事件的时刻）→ 流式输出 → durationMs（AssistantMessage 自带）→ 工具执行（tool_execution_end.durationMs）。悬停请求条可以看到 token、缓存命中与费用；真实模型下还能展开前 20 个原始 chunk。底栏「Span 树」展示 pi-telemetry 收集的 rescue.run → rescue.request / rescue.tool。

## 课程脚本

faux 模式下按以下步骤运行（同时是回归测试）：

1. 一次运行的耗时构成：排队 → TTFT → 流式 → 工具 → 下一次请求

## 关掉它会怎样

不传 onProviderStreamEvent：TTFT 只能用首个流式增量近似（faux 下本来就是这样）
